# FRAMPP v0.6.0 改进计划

> 状态：已实施（2026-08-29）
> 基线：v0.5.0
> 说明：11 项改进已全部收集并实施；实现记录见 `docs/blueprint.md` §2.11 与 CHANGELOG。

## 改进清单

| # | 改进项 | 备注 / 待确认 |
| --- | --- | --- |
| 1 | 安装完成后，清理正式使用中无用的安装脚本：`install.sh` 以及 `installer/` 下不再需要的安装脚本 | 需先盘点安装后哪些脚本实际会被用到 |
| 2 | `uninstall.sh` 不再放在根目录，移动到 `bin/` 或其他合适目录 | 同时确认卸载命令的调用路径 |
| 3 | `Caddyfile` 等配置文件集中到 `etc/` 目录 | 需规划：盘点有哪些配置文件需要集中管理，并统一路径 |
| 4 | `frankenphp`、`python`、`mariadb`、`agent` 等软件不直接放在根目录，统一放入子目录（建议 `modules/`），各自保持独立目录；常用命令通过符号链接到 `bin/` | 参照 XAMPP 前缀安装，但不要求完全一致 |
| 5 | `bin/` 目录收集必要命令，对 `modules/` 中的具体命令通过符号链接统一管理 | 与第 4 条配套 |
| 6 | 现有 `data/` 目录改名为 `var/`，对齐 XAMPP 的 `var` 目录语义 | 需同步调整所有引用路径、文档与安装器 |
| 7 | 安装脚本中的提示语改为中英双语 | 需覆盖 `install.sh`、`uninstall.sh` 及其他安装相关脚本 |
| 8 | 解释并确定 `control-panel/` 与 `templates/` 的作用，并决定它们在安装后布局中的归属 | 需先梳理两者定位，再确定调整方案 |
| 9 | 在 `bin/frampp` 已具备启动命令的基础上，同时生成 `systemctl` 服务启动脚本，以及对应的安装脚本 | 面向 Linux 变体；需确定服务单元文件路径、用户与 `WorkingDirectory` |
| 10 | 在 `bin/` 下提供标准命令包装：`php`（调用 `frankenphp php-cli` 并保持 PHP CLI 兼容）、`composer`、本系统安装的 `python`、`pip`；同时提供 `env` 脚本，把 `bin/` 加入 `PATH` 并设置所需环境变量 | 与第 4、5 条的 `bin/` 命令统一管理配套 |
| 11 | 支持 `caddy-access-filter` v1.2.0，包含本地 IP 地址访问控制与基于 IP 的国家/地区码访问控制；并将该能力集成到管理平台，增加 IP 访问控制功能 | 需核对 v1.2.0 的配置格式，并与现有 `access` / `filter` 集成及安全基线兼容 |

## 优先级与范围

全部 11 项纳入 v0.6.0；跨平台行为在 Windows + Linux CI 中验证。

## 验收标准

- 安装后布局为 `bin/`、`etc/`、`var/`、`modules/`，无根目录 `install.sh`。
- Linux 包可通过 `bin/frampp init` 初始化，`bin/uninstall` 卸载，
  `bin/install-systemd` 安装 systemd 服务。
- `bin/php` / `bin/composer` / `bin/python` / `bin/pip` 可调用内置运行时。
- Linux 控制面板可管理 IP / CIDR / 国家码规则并热重载。
- `tests/run-tests.ps1` 全部通过。

## 未决问题

- Windows 官方预编译 FrankenPHP 未内置 `caddy-access-filter`，IP 访问控制仅
  Linux 定制构建可用；后续若构建 Windows 定制版可移除该限制。
- GeoIP 国家码规则需要用户自行提供数据库文件（如 GeoLite2 Country MMDB）。
- 兼容层保留对旧 `data/` 布局的读取回退，但新安装一律使用 `var/`。
