# FRAMPP v0.8.0 改进计划

> 状态：计划中（2026-09-01）
> 基线：v0.7.1
> 说明：记录 3 项改进；实施前按仓库规则在 `docs/blueprint.md` 补决策记录。

## 改进清单

| # | 改进项 | 现状 | 计划方案 |
| --- | --- | --- | --- |
| 1 | README 全部并入 docs、docs 全部并入 share，并补齐中文版 README | Linux 安装包根目录含 `README.md`（仅英文）、`docs/`（仅 `docs/user/*`）、`VERSION`、`LICENSE`；Windows（`setup.iss`）同样只分发英文 `README.md`（`isreadme`）与 `docs/`；**`README.zh-CN.md` 两个平台均未随包分发** | 安装包根目录不再放 `README.md` / `docs/`，文档统一收进 `share/docs/`：`share/docs/README.md`（英文）、`share/docs/README.zh-CN.md`（中文，补齐）、`share/docs/user/*`（docker / upgrade 等）；README 内容全部并入 docs，仓库根 README 仅作入口/索引，安装包内不再重复 |
| 2 | `frampp start`（TCP 模式）检查端口占用，能判断启动失败 | `ServiceManager::start()` 仅检查服务自身 PID；`startDetached()` 用 `proc_open` 拉起进程后立即返回 PID，不验证端口是否监听成功。TCP 模式下端口（8080 / 8081 / 3306 / 6379 / 2019）被其他进程占用时服务绑定失败，但 `frampp start` 仍返回 `started=true`，用户无法判断启动失败 | 启动前（TCP 模式）预检目标端口（http / panel / mysql / redis / Caddy admin 2019）：端口已开放且非 FRAMPP 自身服务则返回明确错误（含占用提示与建议：`frampp ports` / 换端口）；sock 模式检查 `var/run/*.sock` 占用。启动后轮询端口 / socket 就绪（超时约 10s），结合日志尾部判定结果：就绪 → `started=true`；超时或进程即退 → `started=false` + error（附日志末行），CLI 退出码非零 |
| 3 | VERSION 放入子目录（`etc/`） | Linux 安装包把仓库根 `VERSION` 复制到安装根目录 `VERSION`；`bin/frampp version` 从 `<root>/VERSION` 读取。Windows 安装包根目录无 VERSION（版本号经 `release-defines.iss` 注入） | 安装包内 `VERSION` 移入 `etc/VERSION`（仓库根 `VERSION` 保留，作为构建输入与 CI 读取源）；`self_version()` 读取顺序改为 `etc/VERSION` → 旧 `<root>/VERSION` 兼容回退 |

## 影响面

- 打包脚本与安装器：`installer/scripts/build-linux-package.ps1`、`installer/setup.iss`；
- 运行时读取：`control-panel/bin/frampp`（`self_version()`、start 输出与退出码）、`control-panel/src/ServiceManager.php`（`start()` / `startDetached()` / 端口预检）、控制面板 `web/action.php`；
- 守护与健康检查：`framppd`、`docker-healthcheck.sh`、Dockerfile 内 docs / VERSION 路径；
- 文档互链：README ↔ docs 内链接、升级文档（旧安装目录 `docs/`、根 `VERSION` 与新 `share/docs/`、`etc/VERSION` 并存处理）。

## 优先级与范围

全部 3 项纳入 v0.8.0；跨平台行为在 Windows + Linux CI 中验证。

## 验收标准

- Linux 安装后根目录仅含 `bin/`、`etc/`、`htdocs/`、`logs/`、`modules/`、`share/`、`var/`、`frampp`（符号链接）与 `LICENSE`，无根目录 `README.md` / `docs/` / `VERSION`。
- `share/docs/` 内含 README 英文版与中文版，用户文档齐全；`etc/VERSION` 存在且 `frampp version` 正确输出，旧布局（根 `VERSION`）读取回退可用。
- TCP 模式下 `frampp start`：端口被其他进程占用 → 明确报错、不误报 `started=true`；进程启动即退出 → 返回失败并附日志末行；正常启动 → `started=true`。
- `tests/run-tests.ps1` 全部通过；CI 冒烟（ubuntu + windows）通过。

## 未决问题

- Windows 安装向导 `isreadme` 展示源：保留根目录 README 还是改为 `share/docs/README.md`，需确认 Inno Setup 的 README 路径语义。
- Docker 镜像内是否同步调整 docs / VERSION 位置（镜像内 `/opt/frampp/docs`、`/opt/frampp/VERSION`）。
- 端口占用者识别：是否输出占用进程名（Windows `Get-NetTCPConnection` / `netstat`，Linux `ss` / `lsof`），还是仅提示端口被占用并给出排查建议。
